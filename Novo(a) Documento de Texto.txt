Números negativos com sinal e destaque visual adequado.
13. Importação e processamento técnico
O HTML deverá:

Conter todo o HTML, CSS e JavaScript em um único arquivo;
Permitir importação de arquivos .xlsx e .xls;
Processar os dados diretamente no navegador;
Utilizar JavaScript e uma biblioteca adequada, como SheetJS;
Não utilizar servidor;
Não utilizar banco de dados;
Não utilizar backend;
Não enviar os dados para serviços externos;
Manter os dados apenas na memória do navegador;
Substituir integralmente os dados quando um novo arquivo for carregado;
Recalcular filtros, cards, gráficos, rankings, alertas e textos automaticamente.
Caso sejam utilizadas bibliotecas externas por CDN, informar visualmente no HTML que o arquivo depende de conexão com a internet para carregar essas bibliotecas. Sempre que possível, estruturar o código para evitar erros caso uma biblioteca não seja carregada.

14. Tratamento de dados
Implementar tratamento para:

Células vazias;
Valores nulos;
Textos em campos numéricos;
Valores monetários com diferentes formatos;
Percentuais escritos como texto;
Datas em diferentes padrões;
Datas inválidas;
Campos com espaços extras;
Categorias com diferenças de maiúsculas e minúsculas;
Valores negativos;
Duplicidades;
Colunas sem nome;
Abas vazias;
Arquivo sem estrutura reconhecível;
Ausência de campos necessários para determinada análise;
Divisão por zero;
Períodos sem movimentação.
O sistema deverá:

Não apagar silenciosamente dados inválidos;
Informar quantos registros foram ignorados;
Informar o motivo da exclusão de qualquer registro;
Manter uma seção de diagnóstico;
Evitar que erros em uma coluna impeçam a leitura das demais;
Exibir mensagens claras para o usuário.
15. Flexibilidade para novas planilhas
A planilha utilizada como referência deverá servir apenas para compreender:

Estrutura;
Nome das colunas;
Tipos de dados;
Relacionamentos;
Possíveis cálculos;
Categorias;
Períodos;
Regras de análise.
Não incorporar registros da planilha original ao código HTML.

O HTML deverá ser entregue sem banco de dados interno e sem dados fixos da planilha, inclusive em:

JSON;
Base64;
Arrays;
Variáveis preenchidas com registros;
Tabelas ocultas;
Dados codificados;
Exemplos que possam ser confundidos com dados reais.
Os dados somente poderão ser carregados após o usuário selecionar um arquivo pelo botão de importação.

Quando outro arquivo com a mesma estrutura for carregado:

Os dados anteriores deverão ser removidos da memória;
Os novos dados deverão substituir os anteriores;
Todos os gráficos deverão ser recriados;
Todos os cards deverão ser recalculados;
Todos os filtros deverão ser atualizados;
Todas as comparações deverão ser refeitas;
O resumo executivo deverá ser regenerado;
Os alertas e recomendações deverão ser atualizados.
16. Controle de qualidade das conclusões
Antes de exibir qualquer insight, verificar:

Se o indicador possui dados suficientes;
Se o período de comparação é equivalente;
Se não existem muitos valores ausentes;
Se os valores estão na mesma unidade;
Se o cálculo não mistura receita bruta com receita líquida;
Se custos e despesas não foram duplicados;
Se eventos extraordinários estão separados;
Se a conclusão é compatível com os números;
Se a variação é material ou apenas uma oscilação pequena;
Se a conclusão não está atribuindo causa sem evidência.
Cada insight deverá indicar, quando possível:

Indicador envolvido;
Período;
Valor;
Comparação;
Variação;
Interpretação;
Nível de prioridade.
Classificar os alertas em:

Informativo;
Atenção;
Prioridade alta.
Não utilizar linguagem alarmista. O objetivo é apoiar decisões com clareza e equilíbrio.
